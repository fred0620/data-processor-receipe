# 導覽改版 v2 規格（0.2.1）

依 Frederic 實測回饋修改 0.2.0 的導覽。先讀 `CLAUDE.md`、`docs/onboarding-spec.md`（原規格）、`app/dataprocessor/web/spotlights.js`。本文件和原規格衝突時以本文件為準，完成後把原規格對應段落改掉。

共通限制照舊：Vanilla JS/CSS、CSP（無 inline script、無 eval）、只用 Stageshow token、資料一律 `textContent`、台灣繁體中文、不用破折號、不寫「歡迎」「恭喜」。

## 1. 浮標不寫方向箭頭

問題：浮標文字裡的 ← → ↑ ↓ 是寫死的，浮標實際放在目標的哪一邊由 `positionPointer()` 決定，兩者常常對不上。

- 所有 `pointer` 文字拿掉箭頭，只留動作，例如「按這裡執行」「沒有配對」「試算」。方向只靠浮標本身的三角形（`data-dir`）表示，三角形一定指向目標。
- 引擎在顯示前再保險一次：去掉文字開頭與結尾的 `←→↑↓` 與空白。
- 目標在畫面外：浮標貼在捲動容器的上緣或下緣，文字改成「往上捲」「往下捲」（不加箭頭），三角形指向捲動方向；點浮標無作用（`pointer-events: none` 不變）。
- 測試：全關卡掃描與練習掃描時，每一步浮標文字都不含 `←→↑↓`；浮標三角形方向和浮標相對目標的實際位置一致（三角形朝右時，浮標的右緣小於等於目標的左緣，依此類推）。

## 2. 指令條跟著捲動

問題：`.work` 是捲動容器，`#guideBar` 與 `#missionStrip` 在最上面，往下捲到表格或配對卡片時就看不到現在要做什麼。

- `#guideBar` 與 `#missionStrip` 包進一個 `.guide-dock`，在 `.work` 內 `position: sticky; top: 0; z-index` 高於表格表頭，背景用 `--well`（和 `.work` 同色，捲過去的內容不會透出來），下緣 1px `--line`。`.work` 的上內距 28px 要讓 dock 貼齊頂端（dock 用負 margin 抵銷或把內距移到內容）。
- dock 高度用 `ResizeObserver` 寫進 `--guide-dock-h`；`.work` 設 `scroll-padding-top: calc(var(--guide-dock-h) + 12px)`，讓 `scrollIntoView` 和捲到目標時不會被 dock 蓋住。表格的 sticky 表頭 `top` 也要加上 dock 高度，否則表頭會鑽到 dock 底下。
- 浮標避開 dock（取代原本分開避開兩條的寫法）。
- 細節（`#drawer`）與練習面板在右欄，不受影響。
- 測試：關卡 A 第 6、7、8 步把 `.work` 捲到最底，指令條仍在可視範圍頂端且行動句可讀；目標被捲進 dock 底下時不算可見，浮標改成「往上捲」；表格表頭不和 dock 重疊。

## 3. 關卡 A 要把配對與檢查做完才下載

問題：現在第 7 步處理完 INV-1008 就到「下載」，配對還有待處理（1010 待確認、1005／1006 找不到），結果也還有需檢查的列。教的是「沒做完就下載」。

改成 10 步（`review-1`～`review-10`），前 7 步不變：

| 步 | 標題 | 行動句 | 完成條件 |
|---|---|---|---|
| 8 | 把配對做完 | 依子步驟（動態） | `inv_decl` 沒有待處理的配對（Match 卡片不是橘色，配對分頁「需處理」為 0） |
| 9 | 把剩下的列看完 | 按「確認無誤，下一筆」看完剩下 n 列 | 結果沒有 `status === "review"` 的列（進度顯示「都已處理，可以下載」） |
| 10 | 下載 | 按右上角「下載 Excel」 | 第 9 步完成後才匯出（`demoExported` 在第 9 步完成前發生不算） |

第 8 步子步驟依「目前還沒處理的配對」動態產生，每次推到第一個未處理的：

- 待確認（因為 1009 指定了 AA15A0005，1010 只剩 AA15A0006）：行動句「1010 只剩一筆候選，按『確認正確』」，提醒「人工指定後剩下的候選也要你確認」。
- 找不到、對面也沒有合適的列：行動句「{單號} 沒有報關單，按『沒有配對』」，提醒寫原因（例如「這張發票沒有出口報關」）。
- 實際剩下哪些配對、各是哪一種，先用測試跑一次範例資料列出來，寫進子步驟與本文件的附錄，不要猜。

第 9 步：
- 浮標指細節下方的主要按鈕。目前列有一定要處理的警示（按鈕變成「還有 n 個要處理」）時，浮標改指那個警示的動作，提醒行寫該警示的處理方式（例如「金額讀不懂，改成數字後按 Enter」）。
- 提醒行顯示「還有 n 列，進度條滿了就能下載」，n 即時更新。
- 範例資料必須能在這一步全部處理完；有走不完的情況要回報。

第 10 步：使用者在第 9 步前就按下載也可以，但不推關，提醒行寫「還有 n 列沒看，看完再下載」（`--warning-text` 加 ⚠）。

其他：
- 指令條與進度列寫「n/10」。`prefs` 存的步驟 id 不變，舊的進度若停在原本的 `review-8`（下載），續玩時推到第一個未完成的步驟。
- 完成狀態行動句改為「核對流程走完了」，提醒「每一列都處理過才下載，正式資料也一樣」。主要按鈕見 4.4。

## 4. 進階功能：每一項都帶到完成，並有練習中心

問題：檢查類的 5 張說明卡（`card-trace`、`card-source`、`card-bulk`、`card-reset`、`card-popout`）與 `card-transform` 只指到位置就結束；做完新手導覽後沒有地方讓人看到還有哪些可以練。

### 4.1 每項進階功能都是一條小關卡（mission）

用同一個 Spotlight 引擎、同一套指令條、進度列、浮標、推關規則與子步驟。每條 3～5 步，用範例資料（進入前照 `leaveDemo` 的規則保存使用者的工作），最後一步的完成條件綁真實狀態，不能跳過。進度列左側寫「進階：{標題}」。

| id | 標題（不變） | 步驟與完成條件 |
|---|---|---|
| `mission-trace` | 看這一格是怎麼來的 | 1 打開 INV-1002（列被選取）→ 2 把滑鼠移到「金額」欄名，按「怎麼來的」（該欄的來由顯示出來）→ 3 看原始寫法 `USD 3,450.00` 與整理後的值（來由顯示至少 600ms，或點了原始儲存格位置）→ 4 展開「這一列的處理過程」（處理過程展開且看到配對試了哪些方式） |
| `mission-source` | 兩張表並排，找配對的答案 | 1 到配對分頁，找 INV-1008（找不到）→ 2 按卡片的表格圖示，再按「完整工作表」（原始資料分頁打開且左右並排）→ 3 看右邊橘色「沒用到」的列（點了其中一列的配對欄或列）→ 4 判斷沒有合適的，回到配對按「沒有配對」（INV-1008 為確認沒有） |
| `mission-bulk` | 一次確認很多筆 | 1 打開「所有警示」→ 2 篩選只看「要人判斷」的同一類警示（選了一個類別）→ 3 勾選全部，按「確認無誤」（這一類全部已確認，至少 1 筆）→ 4 切到「已處理」看紀錄（篩選為已處理且看得到剛確認的） |
| `mission-reset` | 清掉重來，按錯可以復原 | 前置：先自動做 2 個人工決定（用 API，和使用者點的結果相同）。1 按「重新檢查」看會清掉幾項（顯示數量）→ 2 再按一次清除（決定數為 0）→ 3 按下方「復原」（決定數回到 2） |
| `mission-popout` | 表格太寬，搬到另一個螢幕 | 1 按「Pop out」把結果搬出去（另一個視窗開啟，主視窗分頁標 ↗）→ 2 在新視窗選一列（主視窗收到同步）→ 3 按「Pop in」或主視窗的「全部 Pop in」（分頁回到主視窗，選到的列帶回）。另開視窗被瀏覽器擋住時，提醒行說明並允許跳過這條關卡 |
| `mission-transform` | 用公式算出新欄位 | 1 打開任一列 → 2 在「台幣金額」按「怎麼來的」（看到計算步驟的 note「換算台幣」）→ 3 按 recipe 的「查看」，在說明裡找到計算那一段並展開「SQL 原文」（說明對話框中 SQL 原文展開）。完成畫面附「複製給 AI 的提問」 |

- 原本 5 個 `lab-*` 練習保留，納入同一個清單（4.3），完成畫面和 mission 一致。
- 說明卡的動作列：主要按鈕統一為「開始練習」（mission 或 lab），「看手冊 ↗」保留；拿掉「試試看」「帶我去」這種指過去就結束的動作。在自己的資料上想直接找位置，改由說明卡內文寫位置（一句）。
- 每條的完成畫面：一句學到什麼、`下一個：{建議的下一項}`（primary，依清單順序找第一個沒練過的）、`回練習清單`、`回到我的工作`（有保存的工作時）。

### 4.2 推薦順序

`mission-trace` → `mission-source` → `mission-bulk` → `mission-reset` → `mission-popout` → `lab-gate` → `lab-mapping` → `lab-match` → `lab-extract` → `lab-validate` → `mission-transform`。

### 4.3 練習中心

新的 `<dialog id="practiceHub">`（寬 720，最高 `calc(100vh - 96px)` 可捲動，Stageshow `.float-card` 的圓角、陰影；不用 `showModal` 以外的寫法時要確認 5.6 的對話框導覽規則仍成立）。

```
進階功能練習                                       已練 3 / 11   ✕
每項 2～4 分鐘，用範例資料操作，做完會接回你的工作。

檢查與修正
┌───────────────────────┐ ┌───────────────────────┐
│ 看這一格是怎麼來的   ✓  │ │ 兩張表並排，找配對的答案 │
│ 不懂某個值為什麼是這樣   │ │ 找不到配對，想自己翻原始表│
│ 約 2 分鐘    再練一次   │ │ 約 3 分鐘       開始    │
└───────────────────────┘ └───────────────────────┘
...
寫 recipe
...
```

- 兩欄卡片網格（寬度不夠時一欄），卡片：標題（14px 600）、什麼時候用（12.5px）、時間、狀態。沒練過的按鈕是「開始」（ghost），推薦的下一項卡片用 1px accent 細框並把按鈕改 primary，全清單只有一個 primary。練過的寫 ✓（`--success-text`）與「再練一次」。
- 入口：
  1. 關卡 A 完成狀態的主要按鈕改為「練習進階功能」（開練習中心），`回到我的工作`／`用自己的資料開始` 降為 ghost。
  2. 「說明 ▾」選單的「進階功能」段落上方加一列「練習中心　已練 n / 11」，點了開練習中心；段落裡每一項仍可直接開說明卡。
  3. 歡迎畫面：關卡 A 完成後，主要入口換成「練習進階功能（已練 n / 11）」，原本「用範例資料邊做邊學」改為次要的「重看新手導覽」。
  4. 使用者第一次用自己的資料執行完、且關卡 A 已完成、練習中心從沒開過時，指令條位置顯示一次靜默提示「看完這份資料後，可以到說明 ▾ 練習進階功能」，附「開練習中心」「不用了」，點任一個或執行下一次後不再出現（記在 `tipsSeen`）。
- 在練習中心點「開始」：關閉對話框，照 `leaveDemo` 的規則保存工作，開始該 mission 或 lab。
- 進度：`prefs` 的 `labsDone` 改名 `practiceDone`（讀舊鍵時遷移），mission 與 lab 共用。

## 5. 測試（補在 tests/ui，一般測試補在 tests）

- 第 1、2 節各自的測試（見各節）。
- 關卡 A 從頭走到第 10 步完成，過程中只用真的點擊與鍵盤；完成時配對分頁需處理 0、結果需檢查 0、匯出檔名有「示範_」。
- 第 9 步前按下載：出現 ⚠ 提示，步驟停在原地。
- 舊進度停在原本的 `review-8`：續玩後推到第一個未完成的步驟。
- 每條 mission 走到完成；最後一步沒有「下一步」可跳過；完成畫面的「下一個」開的是清單順序中第一個沒練過的。
- mission 前有自己的結果 → mission → 回到我的工作，結果、分頁、選到的列都恢復（沿用 `leaveDemo` 的測試方式）。
- 練習中心：從三個入口都能打開；練過的顯示 ✓；推薦項目唯一一個 primary；1000px 寬時改一欄且不超出視窗。
- 全關卡掃描擴充到所有 mission：每一步與子步驟都有可見的強調、行動句不為空、浮標不含箭頭、浮標不蓋到目標以外的可點元素。
